## Standing notes

**Recurring dev-team process lessons (this repo):**
- A producer/consumer field-name mismatch between two wiring items passes both items' own tests (each fake encodes its own author's assumed shape) and fails only live — assert field names against LANE.md's stated shape, not a neighboring module's fake. (Seen in the Places/budget item and again in the e2e pipeline item.)
- Take the test-suite baseline from the suite's own `# pass` line at your actual HEAD, never from a spawn prompt or a declared test-command line — baselines drifted twice in this run because another item committed to the shared branch mid-item.
- Mutation-check safety constants (caps, allow-lists, dedupe keys) against a written-out literal, never against the constant the module exports — widening the constant silently widens the test with it.
- `git status` clean at spawn time is NOT proof a shared worktree is yours alone — two items ran in the same worktree simultaneously twice in this run. Check whether an earlier item's spawn-log row is still `pending` before assuming, and never `git checkout --` to restore a mutation check there — restore from a `cp` backup and verify byte-identical.
- A `dt-orchestrator` returning anything other than the standard DONE/BLOCKED line has NOT finished — check `ListAgents` for live children before dispatching the next item, and stop orphans.

**Repo/schema facts:**
- `main` is the live contract here — Nate merges lane branches to `main` by hand so `workflow_dispatch` works, so `main` is routinely AHEAD of the lane branch (the reverse of the usual arrangement). Before picking a working branch, run `git log --oneline <branch>..main` / `main..<branch>` and pick the tip; never trust a README/progress-file claim that a branch is "level with main."
- Widening a CHECK constraint means re-auditing every EXISTING RLS policy that writes that column (this repo's policies are permissive and written against the narrower vocabulary). `create policy` has no `set search_path` — the convention is fully qualifying every call (`public.is_admin()`, `public.is_staff()`, `auth.uid()`).
- Stage CHECK vocabulary (as of migration 0022, authored but NOT yet applied live): sourced, qualified, call_due, drafted, approved, sent, replied, quoting, meeting, quoted, won, onboarded, lost. `approved` is dead vocabulary — nothing should write it. **0022 is still unapplied against the live DB (`knmgyxlrhjxaydliucbs`)** — anything depending on `onboarded`/`os_slug`/`clients.signed_at`/`contract_path`/`repo_url` only works once a human applies it.
- `tests/migrations.test.mjs` is textual-only (asserts SQL text per an explicit `--- NNNN ---` filename block) — there is no temp-DB replay test and no glob fallback, so a new migration with no block is silently uncovered.
- `research` carries a growing set of JSON keys across the pipeline (`facts`, `fit`, `reason`, `page_text`, `draft`, `pitch_path`, `owner_name`, `notes`) — every writer must spread the parsed object, never rebuild it.
- `os_slug` has no FK to `clients.slug`, on purpose — the funnel row is slugged before the `clients` row exists. Don't assume the FK enforces write order.

**Known-open defects/blockers (as of 2026-09-03):**
- `drafted`/`replied`/`quoting`/`quoted`/`onboarded` notify dedupe markers are never cleared by any code — a row re-entering one of those stages is never renotified again. Only `call_due` re-arms (via `next_touch_at`).
- `personalize` still has no cron cell / `SCHEDULES` entry — `qualified` rows never become `drafted` in production.
- `clock.yml`'s `persist-credentials: false` on the `~/os` checkout means any live (non-dry-run) `commitAndPush` from CI has no git credentials and will fail at push — `pitch` is the first job that actually needs this.
- The 20-minute poll tick runs five jobs at `limit=25`, each row one Claude CLI call at `runSkill`'s 600s default, inside `timeout-minutes: 10` — one slow call kills the tick before later jobs run; needs a lower per-job limit or shorter timeout before going live.
- `deps.verify` opens port 25, which GitHub-hosted runners commonly block — will likely always return `unknown` in production until the probe moves to a relay.
- `sent_today` (mailbox send cap) is never reset — a daily reset job or date column is still owed; until it exists the cap is a lifetime cap, not a daily one. `dueTouches` scans `next_touch_at` with no index in 0018.
- `deps.readVoiceRules` was still not wired into `buildDeps` as of the personalize item — check before assuming voice rules apply to drafts.

**Resolved architecture (context, not action items):**
- The old batch-approval flow (`yes`/`no` + `approvalEmail`) was removed entirely — `yes` is no longer a parseable command anywhere (honoured set: `no`, `no answer`, `stop`, `won <amount>`, `notes`; ordering matters, `no answer` is tested before `no`). This closed the earlier "batch approval is unroutable" defect.
- `buildDeps` separates recipients into three lists: `allowedRecipients` (prospects), `internalRecipients` (internal humans + command senders), `onboardRecipient` (exactly one) — this closed the earlier Critical of one list serving both purposes. Route any new internal-only mail through `internalRecipients`, never the prospect list.
- The dry-run marker rule is now a project standard: any job persisting "this is done" after a `commitAndPush` MUST go through `pushOrSkip` (`lib/osrepo.mjs`), gating the marker write/stage move/success event behind `if (!push) continue` — `pitch`, `quote`, and `poll`'s contract attachment all follow this. A job wrapping an IRREVERSIBLE skill side effect (e.g. `/new-client-repo`'s `gh repo create`) must branch on `dryRun` BEFORE the call using the skill's own `--dry-run`, not skip the marker after.
- Consumers of `runSkill` must expect `dryrun` as an ARRAY and `repo` as a scalar (last `REPO:` line wins). `lib/claude.mjs` is CLI-only via `execFile` — a test asserting "no API key" can just regex the source.
